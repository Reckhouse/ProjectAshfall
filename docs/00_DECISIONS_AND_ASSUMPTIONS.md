# 00 — Decisions and Assumptions

## Locked product decisions

| Area | Decision |
|---|---|
| Platform | Browser |
| Hosting | Vercel application + Neon Postgres |
| World | Persistent square grid |
| Primary controls | Tile-by-tile movement; keyboard support later |
| Resources | Energy and Metal |
| Account base | One initial base per account |
| Spawn | Random valid coordinate generated by server |
| Exploration feature | Caves |
| Cave reward | Tools |
| Tool purpose | Improve resource collection |
| Base army | Defense troops |
| Field army | Offense troops |
| Phase 1 | Authentication + account provisioning + base spawn |

Phase 1 identity is a first-party email/password session stored in Neon (`auth_users` / `auth_sessions`). Game tables reference `auth_user_id` only, so Neon Auth can replace the identity provider later without changing spawn or resources. See `docs/19_PHASE_1_IMPLEMENTATION_NOTES.md`.

## Carry-forward identity from earlier Ashfall

- Deliberately old-school persistent browser strategy feel
- Clear HTML/CSS information panels rather than a heavy 3D interface
- World grid is the central gameplay surface
- Movement is discrete rather than free-roaming
- Strategic loop centers on exploration, gathering, returning, upgrading, recruiting, and eventually raiding
- Defense and offense must remain easy to understand at a glance

## Recommended assumptions

These are defaults for implementation planning and can be tuned later.

### Movement
- Cardinal movement only at first:
  - north
  - south
  - east
  - west
- Arrow keys and WASD can both map to these commands
- Manhattan distance is the default path-distance model

### World
- One active world/season at first
- Chunked map
- Terrain generated deterministically
- Bases/caves/mutable resource state persisted
- Empty tiles are not stored individually

### Game pacing
- Asynchronous persistent strategy
- Useful short sessions
- Passive progression prevents soft locks
- Active exploration must outperform purely passive waiting

### Combat
- Not implemented in Phase 1
- Server-resolved
- Defender receives modest base advantage
- Field offense is physically unavailable to defend home while away

## Explicit Phase 1 non-goals

Do not implement:

- playable world movement
- resource harvesting
- caves
- tools
- troops
- combat
- PvP
- alliances
- trading
- chat
- realtime presence
- seasons
- leaderboards
- marketplace
- real-money purchases
- advanced admin panel

Create future-facing interfaces only when they prevent a known dead end.
